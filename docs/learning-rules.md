# 学习与协作约定

## 1. 总目标

AI 可以帮助执行命令、编写代码和排查错误，但最终目标不是“AI 把项目写完”，而是学习者能够：

- 解释主要业务请求经过了哪些层。
- 独立完成小范围功能修改。
- 根据错误信息找到大致的问题位置。
- 在面试中诚实、清晰地讲述项目取舍。

## 2. 开发原则

1. 优先完成业务闭环，不提前进行性能优化。
2. 每次只引入当前功能必须使用的新知识。
3. 新需求默认进入 `backlog.md`，不能打断当前课程。
4. 第一次实现以简单、正确、可验证为目标。
5. 优化必须由真实问题、测试结果或明确需求驱动。

## 3. 讲解原则

1. 默认学习者是全栈和 AI 应用初学者。
2. 新概念第一次出现时，要用通俗语言解释它解决的问题。
3. 关键代码要解释输入、输出和调用关系，不逐字符讲解语法。
4. 不使用“这个很简单”“显然”之类跳过思考过程的表达。
5. 框架提供的魔法行为必须指出发生时机和作用。

## 4. 每课互动流程

每一课都必须依次经过下面几个阶段：

1. **分析与分工**：AI 先说明本课目标、核心流程、涉及文件，以及哪些内容由 AI 创建、哪些核心代码必须由学习者亲手完成。
2. **学习者实现**：AI 按检查点布置有限任务，学习者亲手完成核心文件、代码和命令；概念题可以口答或自行思考，不强制逐题发送文字。
3. **检查与整改**：AI 检查实际文件、代码和命令输出，说明问题并整改；进入下一阶段时给出概念题参考答案和易错点，供学习者自行对照。
4. **运行与验收**：学习者亲自执行关键命令，完成运行检查和一个小修改。只有安全风险、破坏性操作或会直接影响下一步的关键误解需要暂停纠正。
5. **总结与定档**：补全本课教程和课程总结，核对 Git 差异并创建一次有意义的提交。

课程状态按以下顺序推进：

```text
未开始 → 分析与分工 → 等待学习者实现 → 检查整改 → 验收总结 → 已完成
```

只有双方明确确认“本课验收通过”，才能把课程标记为已完成并进入下一课。一次回复结束不代表一课结束，AI 不得自动跳到下一课。

## 5. 文件与课程记录原则

- `docs/` 只保存稳定的产品需求、协作规则和待办事项。
- `lesson/README.md` 只保存课程路线和完成状态。
- 每节课只维护一个课程文件，不再为计划、笔记、答案和总结分别创建文件。
- 课程文件在教学过程中动态更新，但不记录逐轮问答流水和每次错误尝试。
- 每个阶段只保留目标、核心讲解、实际结果、参考答案和易错点，避免课程文件过长。
- 课程结束后补全“完整教程”和“课程总结”，通过验收后定档；定档前保持“进行中”状态。
- 新建文档前先判断内容能否放进现有文件，避免占位文档和重复进度记录。

### 课程会话命名与衔接

- 每节课使用独立会话，统一命名为 `NoteMind 第XX课：课程主题`，课程编号固定使用两位数字。
- 例如：`NoteMind 第01课：Git与项目起点`、`NoteMind 第02课：FastAPI最小后端`。
- 每课收尾时，AI 必须根据 `lesson/README.md` 给出下一课的准确会话名称；学习者不需要再到其他会话询问命名。
- 下一课只能在当前课程验收通过后开始。新会话仍需先读取项目中的学习规则、课程路线和上一课定档内容。

## 6. 命令记录原则

下面类型的命令必须写入对应课程：

- 初始化项目或依赖
- 创建、升级数据库结构
- 启动前端、后端和数据库
- 执行测试、检查和构建
- Git 阶段性提交
- 部署项目

每条重要命令必须说明：

1. 在哪个目录执行。
2. 为什么执行。
3. 它会修改或启动什么。
4. 如何判断执行成功。

仅用于临时查看目录、搜索代码的诊断命令不必全部记录，避免课程变成流水账。

### AI 代执行命令的透明原则

- AI 可以代为执行安全的只读检查，但不能只给出检查结论；对学习者今后可以复用的检查，必须同时说明执行目录、实际命令、用途和关键输出。
- 如果代执行的命令属于本课核心技能，AI 不能以自己的执行代替学习者实践，仍应安排学习者亲手执行或完成等价验收。
- 仅供 AI 临时定位文件、搜索文本或核对内部状态的命令，可以不逐条记录；但其结果如果影响课程决策，必须解释依据。
- 课程文件应区分“AI 检查结果”和“学习者实际操作”，避免把尚未亲手完成的步骤记录为学习者已完成。

## 7. 每课完成标准

每一课必须包含：

- 明确且有限的学习目标
- 本课需要理解的核心概念
- AI 与学习者的实现分工
- 实际修改过的文件
- 执行过的重要命令
- 可以亲自操作的验收步骤
- 常见错误或实际踩坑
- 复习问题、参考答案和一个小练习
- 对本课完整过程的教程
- 可以快速回顾的课程总结
- 一次有意义的 Git 提交
- 双方明确确认“本课验收通过”
- 已给出下一课的准确会话名称

实际文件、代码、关键命令、运行验收和 Git 提交没有完成时，不能进入下一课。概念题由学习者自行对照参考答案，不要求反复书面补答。

## 8. 学习检查

每课结束从三个角度自查：

- **复述**：能否用自己的话解释本课的数据流或执行过程？
- **修改**：能否不照抄地完成一个小变化？
- **排错**：关键配置出错时，是否知道从哪里开始检查？

概念问题可以口答或心里作答。AI 在下一阶段给出参考答案和易错点，学习者自行对照；不因普通概念题答错反复增加问答轮次。涉及安全或会影响后续操作的误解除外。
