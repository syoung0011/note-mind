# NoteMind 产品迭代路线

## 1. 迭代目标

课程 MVP 已经证明核心技术链路可以运行。后续开发以“做出普通用户愿意使用的产品”为第一目标，不为尚未出现的问题提前增加复杂度。

优先级按下面的顺序判断：

1. **主流程缺口**：缺少后用户无法完成注册、登录、记笔记或提问，优先处理。
2. **基础产品体验**：让页面结构清晰、操作可理解、错误有反馈，紧随主流程完成。
3. **随功能完成的基础安全**：服务端校验、数据隔离、密码哈希、权限检查和密钥保护不能推迟。
4. **增强功能**：搜索、对话历史、导入和内容组织，根据真实使用需要逐版加入。
5. **系统性安全和性能优化**：限流、审计、备份策略、数据库索引、缓存等，在功能稳定并出现实际需求或测量证据后处理。
6. **精细体验**：复杂动画、主题系统和高度定制设计最后考虑。

## 2. 当前短期目标：v0.2.0

v0.2.0 的目标是把演示型 MVP 改造成具备完整入口、清晰结构和基础反馈的产品。

### 必须完成

- 使用 Git 标签和 GitHub Release 固定 `v0.1.0`。
- 使用短期功能分支练习开发、检查、合并和清理流程。
- 建立统一的前端应用骨架和基础视觉规范。
- 增加前端注册页面，并打通注册、登录和退出流程。
- 整理笔记列表、编辑区域和 AI 问答区域的页面结构。
- 为加载、空数据、成功和失败状态提供基础反馈。
- 补充必要测试，发布 `v0.2.0`。

### 安全边界

本版本不安排系统性安全专项，但每项功能都必须守住基础边界：

- 所有权限和输入校验以服务端为准，不能只依赖前端。
- 继续使用密码哈希，不记录或返回明文密码。
- 用户只能访问自己的笔记、切块和问答上下文。
- 密钥和真实环境变量不得提交到 Git。
- 页面渲染用户内容时不引入不受控 HTML。

### 明确后置

- 数据库索引分析、查询调优、缓存和异步任务。
- 登录限流、审计日志、刷新令牌轮换和更完整的安全响应头。
- SSE、对话历史、标签、笔记本、Markdown/PDF 导入。
- 混合检索、Reranker、Agent 和复杂评测平台。
- 深色模式、复杂动画和主题定制。

## 3. 后续方向

下面只记录方向，不提前拆成详细课程；每个版本开始前再根据实际使用情况确定范围。

- **v0.3 日常可用性**：搜索、分页或增量加载、未保存提醒、删除确认和基础移动端适配。
- **v0.4 AI 交互**：对话历史、流式回答、引用展开、复制和重新生成。
- **v0.5 内容组织**：标签、笔记本、Markdown 导入，以及确有需要时的 PDF 导入。
- **v0.6 可靠性与安全**：密码管理、限流、令牌策略、备份恢复、日志监控和端到端测试。
- **v1.0 正式作品版**：完整的新用户流程、稳定部署、清晰文档、产品截图和可公开演示的质量。

版本方向不是承诺清单。上一版本验收后，才能细化下一版本；没有真实问题或测量证据时，不提前实施性能优化。
