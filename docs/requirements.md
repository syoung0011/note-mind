# NoteMind 第一版需求

## 1. 产品目标

NoteMind 帮助用户记录学习笔记，并通过 AI 从自己的笔记中查找和总结知识。

第一版的成功标准不是功能多，而是完整跑通下面的核心流程：

```text
注册 → 登录 → 创建笔记 → 建立知识索引 → 提问 → 获得带引用的回答
```

## 2. 目标用户

需要整理课程、技术文档和个人学习资料的学生或开发者。

第一版只考虑单个普通用户角色，不设计管理员、团队和付费系统。

## 3. 第一版必须实现

### 3.1 用户

- 用户名和密码注册
- 用户名和密码登录
- 查看当前登录用户
- 退出登录

### 3.2 笔记

- 创建笔记
- 查看自己的笔记列表和详情
- 编辑自己的笔记
- 删除自己的笔记
- 用户之间的数据必须隔离

### 3.3 AI 问答

- 保存笔记后，将正文切分成适合检索的片段
- 为片段生成向量并保存
- 根据用户问题检索相关片段
- 让大模型基于检索结果回答
- 返回引用的笔记标题和原文片段
- 没有足够资料时明确说明不知道

### 3.4 交付

- Docker Compose 可以启动完整项目
- README 包含启动方法和演示说明
- 关键业务具备基础自动化测试
- 项目可以部署并供他人体验

## 4. 第一版明确不做

- 标签、文件夹、置顶、回收站和分享
- 富文本或复杂 Markdown 编辑器
- 多智能体协作
- 模型微调和强化学习
- Redis、Celery、Kubernetes 和微服务
- 为尚未出现的性能问题提前优化

新想法先记录到 `docs/backlog.md`，不能直接扩大当前课程范围。

## 5. 第一版核心数据

计划使用三张核心表：

- `users`：用户账号和密码哈希
- `notes`：用户创建的笔记
- `note_chunks`：用于 AI 检索的笔记片段和向量

具体字段在实现对应功能时再设计，避免过早设计。

## 6. 第一版接口草案

```text
POST   /api/auth/register
POST   /api/auth/login
GET    /api/auth/me

GET    /api/notes
POST   /api/notes
GET    /api/notes/{id}
PUT    /api/notes/{id}
DELETE /api/notes/{id}

POST   /api/chat
```

接口草案可以随着实际开发调整，但每次调整必须说明原因。
