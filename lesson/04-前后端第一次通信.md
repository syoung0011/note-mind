## 3. 核心请求链路

```text
浏览器打开 http://127.0.0.1:5173
        ↓ Vue 组件挂载后发起 fetch
GET http://127.0.0.1:8000/health
        ↓ FastAPI 路由处理请求
返回 JSON：{"status": "ok"}
        ↓ 浏览器解析响应并更新响应式状态
Vue 重新渲染：后端连接正常
```

- **HTTP 请求**：前端向后端发送方法、地址和可选数据；本课使用不会修改数据的 `GET`。
- **JSON**：前后端交换结构化数据的文本格式；FastAPI 会把 Python 字典转换为 JSON。
- **异步等待**：网络响应不会立刻返回，`await` 表示等待异步结果，同时不阻塞整个页面。
- **响应式状态**：Vue 的 `ref` 保存会变化的数据，赋值后页面会自动重新渲染。
- **生命周期**：`onMounted` 在组件首次挂载到页面后运行，适合触发本课的首次请求。
- **CORS**：浏览器把协议、主机或端口不同视为不同来源；后端必须明确允许前端来源读取响应。

## 5. 最小完整样例

后端将在创建 `FastAPI` 应用后加入 `CORSMiddleware`，只允许本课实际使用的前端来源：

```python
from fastapi.middleware.cors import CORSMiddleware

app.add_middleware(
    CORSMiddleware,
    allow_origins=["http://127.0.0.1:5173"],
    allow_methods=["GET"],
    allow_headers=["*"],
)
```

前端将在组件挂载后请求健康检查接口，并分别保存加载、成功和错误状态：

```javascript
import { onMounted, ref } from 'vue'

const backendStatus = ref('正在连接后端…')

onMounted(async () => {
  try {
    const response = await fetch('http://127.0.0.1:8000/health')
    if (!response.ok) {
      throw new Error(`HTTP ${response.status}`)
    }
    const data = await response.json()
    backendStatus.value = data.status === 'ok' ? '后端连接正常' : '后端状态异常'
  } catch (error) {
    backendStatus.value = '后端连接失败'
    console.error(error)
  }
})
```

这里显式检查 `response.ok`，因为 `fetch` 遇到 404、500 等 HTTP 响应时通常不会自动进入 `catch`；网络断开、CORS 拒绝或代码主动抛出错误时才会进入错误分支。

## 11. 复习问题、参考答案与小练习

1. **为什么前端和后端都使用 `127.0.0.1`，仍然需要 CORS？**  来源由协议、主机和端口共同决定；前端使用 5173，后端使用 8000，端口不同就是不同来源。
2. **FastAPI 返回 Python 字典后，浏览器收到什么？**  FastAPI 将字典序列化为 JSON 响应；前端通过 `response.json()` 把 JSON 解析为 JavaScript 数据。
3. **为什么请求放在 `onMounted` 中？**  它会在组件首次挂载后运行，适合触发这个页面首次加载所需的请求，并明确请求发生的时机。
4. **为什么 `backendStatus` 使用 `ref`？**  连接状态会在异步请求完成后变化；`ref` 让 Vue 追踪变化并自动重新渲染模板。
5. **为什么还要检查 `response.ok`？**  `fetch` 收到 404 或 500 响应时通常仍算完成请求，不会自动抛错；显式检查后才能把非成功 HTTP 状态转入统一错误处理。

小练习：把后端停止后刷新页面，再重新启动后端并刷新。预期页面先显示“后端连接失败”，随后恢复为“NoteMind API 连接正常”。学习者已经亲手完成并验证两条分支。

易错点：CORS 是浏览器执行的安全限制，不等于后端接口自身不可访问；直接在地址栏打开 `/health` 成功，也不能证明 Vue 页面拥有读取响应的权限。排错时应同时检查浏览器 Console、Network、请求地址、后端日志和 CORS 响应头。

## 14. 完整教程

本课从两个已经能够独立运行的应用出发，建立了第一条完整的前后端请求链路：

```text
Vue 组件挂载
→ fetch 请求 FastAPI /health
→ FastAPI 返回 JSON
→ 浏览器解析响应
→ 修改 Vue ref
→ 页面重新渲染连接状态
```

实现时，后端通过 `CORSMiddleware` 允许实际使用的本地 Vue 来源；前端在 `onMounted` 中发起请求，使用 `await` 等待 HTTP 响应和 JSON 解析，并通过 `response.ok`、业务状态与 `try/catch` 区分成功和失败。`backendStatus` 与 `connectionState` 使用 `ref` 保存会变化的数据，使页面能够自动更新文案和颜色。

运行验收时，应分别启动后端和前端。直接打开 `/health` 只能证明接口可访问；只有 Vue 页面成功读取响应、Network 显示 200 且 Console 无错误，才能证明跨来源通信完成。后端未启动时出现 `Failed to fetch`，说明浏览器没有取得可用响应，排错顺序应从端口监听、后端日志、接口直访、请求地址和 CORS 开始，而不是直接认定 `fetch` 语句错误。
