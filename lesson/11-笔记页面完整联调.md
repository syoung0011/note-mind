## 1. 本课目标与边界

本课把已经完成的前端认证与后端笔记 CRUD 接口连接起来，让登录用户能够在页面中完成笔记的完整生命周期。

完成后应当能够解释：

- 页面首次进入时怎样取得当前用户的笔记列表。
- 创建、编辑、删除操作分别对应哪个 HTTP 方法和接口。
- Bearer Token 怎样被复用到所有受保护的笔记请求中。
- Vue 响应式状态变化后，列表、表单和详情为什么会自动更新。
- 加载、空列表、请求失败和删除确认分别解决什么交互问题。

本课业务闭环：

```text
登录进入首页
  → 携带 Token 获取自己的笔记列表
  → 创建笔记并更新列表
  → 选择笔记查看完整内容
  → 编辑并保存笔记
  → 确认后删除笔记
```

本课不新增后端接口或数据库迁移，不实现标签、搜索、Markdown 编辑器、自动保存和 AI 问答；AI 能力从第 12 课开始。

## 2. 当前基础

## 5. 检查点 A：数据流与状态划分

后端数据库是笔记的持久化来源，前端响应式变量是当前页面为了展示和交互保存的临时状态。页面不能只修改本地数组就假装保存成功，而应先调用后端；请求成功后，再用后端返回的数据同步页面状态。

本课页面至少需要区分四类状态：

1. **业务数据**：笔记列表、当前选中的笔记。
2. **表单数据**：正在输入的标题和正文，不能在用户输入时直接修改已保存笔记。
3. **请求状态**：是否正在加载或保存，用于防止重复操作并给出反馈。
4. **错误状态**：保存最近一次可向用户说明的问题，成功操作后应及时清除。

接口与页面动作的对应关系：

| 页面动作 | HTTP 请求 | 成功后的页面同步 |
| --- | --- | --- |
| 进入页面 | `GET /api/notes` | 替换笔记列表 |
| 创建笔记 | `POST /api/notes` | 加入返回的新笔记并选中它 |
| 查看详情 | `GET /api/notes/{id}` | 显示服务端返回的完整笔记 |
| 保存编辑 | `PUT /api/notes/{id}` | 用返回结果替换旧笔记 |
| 删除笔记 | `DELETE /api/notes/{id}` | 从列表移除并清空或切换选中项 |

每个请求都必须携带第 10 课保存的 Token。Token 解决“你是谁”，后端查询中的 `user_id` 条件解决“你只能访问谁的数据”；前端隐藏按钮并不是数据安全边界。

进入检查点 B 前，请先口头思考：

1. 为什么编辑表单不能直接绑定到列表里的原笔记对象？
2. 为什么删除接口成功后不能无条件执行 `response.json()`？
3. 为什么前端即使只展示当前用户的笔记，后端仍然必须按 `user_id` 查询？

无需书面提交答案。进入检查点 B 时会先给出参考答案，再建立笔记 API 服务。

参考答案：

1. 如果表单直接绑定列表中的原对象，用户输入时就会提前改变页面中的已保存数据，即使取消编辑或请求失败也难以恢复；独立表单副本能把“正在编辑”和“已经保存”分开。
2. 删除成功返回 `204 No Content`，响应没有正文；无条件执行 `response.json()` 会因为没有可解析内容而报错。
3. 浏览器页面和请求都可以被用户修改，前端筛选不能形成安全边界；后端必须根据已验证的当前用户添加 `user_id` 条件，才能阻止读取或修改其他用户的数据。

## 6. 检查点 B：携带 Token 的笔记 API 服务

笔记页面不直接重复编写五份完整的 `fetch`。`frontend/src/services/notes.js` 使用 `requestNotes()` 集中处理共同逻辑：

- 组合 `/api/notes` 请求地址。
- 从第 10 课的认证模块取得 Token。
- 添加标准 `Authorization: Bearer <token>` 请求头。
- 优先读取后端错误响应中的 `detail`。
- 对 `204 No Content` 返回 `null`，其余成功响应解析为 JSON。

`listNotes()` 和 `getNote()` 展示了集合地址与单条资源地址的差别；`updateNote()` 展示了 JSON 写请求的完整结构。学习者补全 `createNote()` 与 `deleteNote()`，练习从接口语义推导请求配置，而不是重复抄写整个服务。

易错点：展开 `options.headers` 必须发生在添加 `Authorization` 之前，否则调用方传入的同名字段可能覆盖真正的 Token；`Content-Type` 只在发送 JSON 正文时需要，GET 和 DELETE 本课都没有请求体。

学习者正确选择了创建请求的 `POST`、JSON 请求头和序列化正文，也正确选择了删除请求的资源地址与 `DELETE`。创建请求初次把配置对象写成 `requestNotes(options = {...})`，这会把对象放到 `path` 位置，并在 ES 模块中因给未声明变量赋值而报错；AI 改为显式传入空路径和第二个配置参数。删除请求初次添加了没有必要的 JSON 请求头，AI 将其移除并统一格式。

## 7. 检查点 C：列表、空状态与创建表单

首页改为笔记工作区，并在组件挂载后调用 `listNotes()`。列表加载使用 `try/catch/finally` 分别处理成功数据、错误消息和必定结束的加载状态；模板根据 `isLoading`、数组长度和实际数据依次展示加载提示、空状态或笔记列表。

创建表单使用独立的 `newTitle` 与 `newContent`，避免输入过程影响已经保存的笔记。学习者需要补全 `handleCreate()`：开始时清除旧错误并锁定提交按钮，调用后端创建笔记，成功后把后端返回对象加入列表开头并清空两个输入框，失败时显示错误，最后恢复按钮。

易错点：必须使用后端返回的新笔记，因为其中包含数据库生成的 `id` 和时间字段；不能只把本地表单对象加入列表。数组是 `ref` 保存的值，因此更新时需要访问 `notes.value`。

学习者正确实现了错误清理、提交状态、请求参数、成功后清空表单以及 `catch/finally`。初次调用 `createNote()` 时遗漏 `await`，得到的是 Promise；同时使用 `note + notes.value` 尝试更新数组，会执行加法或字符串拼接。AI 改为等待后端返回对象，再用 `notes.value.unshift(createdNote)` 将其加入列表开头，并删除教学注释、统一格式。

## 8. 检查点 D：选择、编辑与删除

点击列表项时，页面调用 `GET /api/notes/{id}` 获取最新详情，并把标题和正文复制进独立编辑表单。编辑表单不会直接绑定 `selectedNote`，所以输入期间列表仍表示最后一次成功保存的状态。

学习者需要补全两个操作：

- `handleUpdate()`：锁定保存按钮，调用更新接口，用返回对象替换 `selectedNote` 和列表中的同 ID 项，并在 `finally` 中恢复按钮。
- `handleDelete()`：先让用户确认，确认后锁定删除按钮并调用删除接口；成功后过滤列表并清空选中状态，最后恢复按钮。

易错点：更新数组中的对象时应按稳定的 `id` 查找，不能依赖对象引用或标题；删除确认被取消时应直接返回，不能进入请求状态；删除接口成功返回 `null` 是正常结果，页面依据原有 `selectedNote.id` 清理本地状态。

学习者正确判断出更新需要调用 `updateNote()`，删除前需要调用 `window.confirm()`，并尝试在成功后同步列表和选中状态。初次实现没有通过 `.value` 操作 ref，使用了未定义的 ID，向接口传入了 ref 本身，而且 `findIndex()`、`filter()` 缺少判断函数与结果赋值，也没有用 `try/catch/finally` 恢复请求状态。AI 保留原有意图，补全按 ID 更新和过滤数组、取消删除、错误捕获、编辑框清理和按钮恢复，并删除教学注释。

## 9. 检查点 E：错误与认证失效

加载、创建、保存和删除分别使用独立状态，避免一个请求错误地锁住所有操作。所有失败响应会优先展示后端 `detail`；笔记服务还把 HTTP 状态码附加到错误对象，使页面能够区分普通业务错误和认证失效。

普通错误应保留当前页面并显示消息。`401 Unauthorized` 表示 Token 已失效：前端应调用 `logout()` 清除本地 Token 和当前用户，再跳转登录页，不能只显示错误后继续留在受保护页面。

学习者补全 `handleRequestError()`：当 `error.status === 401` 时退出并等待路由跳转，然后立即返回；其他情况把 `error.message` 写入 `errorMessage.value`。

易错点：HTTP 状态码不能通过错误文案判断；错误文案可能变化或被翻译，状态码才是稳定的程序分支依据。跳转登录页前仍需清除 Token，否则下一次认证恢复还会重复携带失效凭证。

学习者正确使用 `error.status === 401` 区分认证失效，调用已有退出流程清理认证状态，并让普通错误继续显示 `error.message`。初次调用异步 `handleLogout()` 时没有等待其路由跳转；AI 补上 `await`，删除教学注释并统一格式。列表、创建、详情、编辑和删除的捕获分支均已接入统一错误处理。

## 13. 复习问题与参考答案

1. **创建笔记为什么要把后端返回对象加入列表？** 后端返回对象包含数据库生成的 `id`、创建时间和更新时间；本地表单只有标题和正文，不能代表持久化后的完整资源。
2. **为什么编辑表单不直接绑定列表对象？** 独立表单能隔离尚未保存的输入；取消、失败或继续浏览时，列表仍表示最后一次成功保存的数据。
3. **删除成功为什么不能直接解析 JSON？** 后端返回 `204 No Content`，响应没有正文；服务层应直接返回 `null`。
4. **Vue 中 ref 和数组分别怎样更新？** 脚本中通过 `.value` 访问 ref；数组可用 `unshift()` 增加、按索引替换，或把 `filter()` 返回的新数组重新赋给 `.value`。
5. **为什么 `401` 要清除 Token 并跳转？** `401` 表示当前凭证不能再证明用户身份；继续保留 Token 会让后续请求重复失败，也会让页面表现成虚假的登录状态。
6. **前端只显示当前用户笔记，为什么后端仍要过滤 `user_id`？** 前端代码和请求都能被修改，数据安全必须由后端根据验证后的当前用户限制查询、更新和删除范围。

## 14. 完整教程

笔记页面挂载后调用服务层的 `listNotes()`。服务层从认证模块读取 Token，统一添加 Bearer 请求头，再调用后端受保护接口。后端验证 Token、取得当前用户，并只查询该用户的笔记；成功数据返回页面后写入响应式数组，Vue 自动更新列表和数量。

创建、编辑和删除都遵循“先请求后端，成功后同步本地状态”的顺序。创建使用后端返回的新对象加入列表；编辑通过稳定 ID 替换列表中的对应对象；删除成功后过滤列表并清空编辑状态。独立的表单数据避免用户输入提前污染已保存数据，独立的加载状态防止重复提交。

服务层对普通成功响应解析 JSON，对 `204` 返回 `null`，对失败响应保留 HTTP 状态码和后端错误详情。页面遇到普通错误时显示消息，遇到 `401` 时清理认证并跳转登录页。最终通过生产构建、真实 CRUD、刷新持久化、无效 Token 和双账号数据隔离验证了完整链路。
