# NoteMind 课程索引

NoteMind 的学习记录按产品次版本分目录保存。Git 标签负责冻结可运行的代码版本，课程目录负责整理该版本的目标、过程和复习材料。

## 版本课程

| 版本 | 状态 | 目标 | 课程入口 |
| --- | --- | --- | --- |
| v0.1 MVP | 已完成 | 从零跑通全栈、RAG、测试与部署 | [v0.1-mvp/README.md](v0.1-mvp/README.md) |
| v0.2 产品化 | 进行中（发布收尾） | 补齐产品入口、页面骨架和基础反馈 | [v0.2-product/README.md](v0.2-product/README.md) |

## 课程目录规则

- 一个次版本使用一个目录，例如 `v0.2-product/`。
- 补丁版本不单独建立课程目录，例如 `v0.2.1` 仍属于 `v0.2-product/`。
- 每个版本目录包含一份 `README.md`，只维护该版本目标、课程顺序和完成状态。
- 每节课仍只维护一个课程文件，进入“分析与分工”时创建，验收后定档。
- 已完成版本原则上不再扩展范围；必要的纠错使用独立提交说明原因。

## 会话命名

新阶段采用下面的格式：

```text
NoteMind v0.2 第01课：MVP定档与Git分支协作
```

每课结束时，根据当前版本目录的 `README.md` 给出下一课准确名称。只有当前课程验收通过后，才能开始下一课。
