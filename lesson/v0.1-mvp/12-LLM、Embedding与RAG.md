## 5. 检查点 A：职责地图

### LLM

LLM 接收文本上下文和指令，继续生成最可能、最符合指令的文本。在 NoteMind 中，它负责根据“用户问题 + 检索到的笔记片段”组织回答。它不是数据库，也不会自动读取项目里的笔记。

### Embedding

Embedding 模型把一段文本转换成一组数字，也就是向量。语义越接近的文本，向量通常越接近。在 NoteMind 中，它负责把笔记片段和用户问题放进同一个可比较的语义空间；它本身不负责生成最终回答。

### RAG

RAG 是 Retrieval-Augmented Generation，即“检索增强生成”。它不是某一种模型，而是一条应用流程：先从外部知识中检索相关内容，再把这些内容作为上下文交给 LLM 生成答案。

可以把三者的关系压缩为：

```text
Embedding：把文本变成可比较的数字表示
Retrieval：用问题找到相关笔记片段
LLM：基于问题和检索片段组织回答
RAG：把检索与生成串成完整流程
```

### 两条不同的数据路径

RAG 系统一般包含两条路径：

1. **索引路径**：笔记发生创建或更新后，切块、生成向量并保存；它准备以后可检索的知识。
2. **问答路径**：用户提问时，为问题生成向量、检索 Top K 片段，再让 LLM 基于片段回答。

删除或更新笔记时，索引也必须同步；否则检索可能拿到旧内容。用户隔离也必须延伸到检索层，不能让用户 A 检索到用户 B 的片段。

### 当前思考题

请先口头思考，不需要提交长答案：

1. 为什么只把全部笔记直接交给 LLM，不适合作为长期方案？
2. Embedding 模型返回的向量为什么不能直接当作自然语言答案？
3. RAG 已经检索到了相关片段，为什么 LLM 仍可能答错？
4. NoteMind 的向量检索为什么也必须带上当前用户的身份范围？

进入检查点 B 时会先给出参考答案，再通过一个具体数字例子解释相似度和 Top K。

### 检查点 A 参考答案

1. 全部笔记可能超过模型的上下文窗口；输入越长，调用成本和延迟通常也越高，大量无关内容还会干扰回答。检索的作用是先缩小范围。
2. 向量是一组供程序计算距离或相似度的数字，不是面向用户组织的自然语言，也不包含“应该怎样回答”的指令。
3. 检索结果可能不完整、不相关或已经过期；即使上下文正确，LLM 仍可能误解内容、忽略限制或生成上下文没有支持的说法。因此后续还需要引用、拒答和基础评测。
4. 向量检索也是数据访问。若只按相似度搜索而不限制 `user_id`，语义上最接近的结果可能来自其他用户，造成数据泄露。

## 6. 检查点 B：向量、相似度与 Top K

### 向量表示什么

向量可以先理解成文本在多个“语义方向”上的坐标。真实 Embedding 往往有数百或数千维，人无法逐维解释；下面用二维数字演示计算关系，而不是模拟真实模型质量。

假设问题向量和三个片段向量为：

```text
问题 Q       = [1.0, 0.0]
片段 A       = [0.8, 0.2]
片段 B       = [0.0, 1.0]
片段 C       = [0.6, 0.8]
```

### 余弦相似度

余弦相似度比较两个向量的方向：

```text
cosine(a, b) = (a · b) / (||a|| × ||b||)
```

- `a · b` 是点积：对应位置相乘后相加。
- `||a||` 是向量长度。
- 方向越接近，余弦相似度越接近 `1`；方向相反时接近 `-1`；互相垂直时为 `0`。

将上面的向量代入，可得到近似结果：

```text
similarity(Q, A) ≈ 0.970
similarity(Q, C) = 0.600
similarity(Q, B) = 0.000
```

所以检索排序为 `A → C → B`。计算使用的是向量，而最终返回给 LLM 的仍是向量所对应的原文片段。

### Top K

`Top K` 表示只取相似度最高的 K 个结果：

- `K = 1` 时只返回 A，上下文短，但可能遗漏补充信息。
- `K = 2` 时返回 A、C，信息更完整，也会增加输入长度。
- K 过大会带入更多无关片段，增加成本并干扰回答。

Top K 只限制结果数量，不保证这些结果真的相关。因此实际系统还可能设置最低相似度阈值：如果最高分都太低，就不应硬凑 K 条内容，而应进入“资料不足”的拒答逻辑。

### 必须分清的三件事

1. **相似度不是正确率**：分数高只表示向量空间里更接近，不表示片段一定正确或足以回答问题。
2. **排序不是生成**：向量检索负责选择原文，LLM 才负责组织答案。
3. **维度必须兼容**：问题和笔记片段必须使用同一个 Embedding 模型及相同配置生成向量，否则不能直接比较。

3. 删除一篇笔记后只删除 `notes` 记录、不删除对应向量，会产生什么问题？

### 检查点 B 参考答案

## 8. 检查点 D：映射到 NoteMind 的完整 RAG 数据流

最小实验把向量直接写在 Python 列表里。真实 NoteMind 中，问题向量由 Embedding 模型临时生成，片段向量则需要随笔记预先建立并保存在数据库中。

### 索引路径：把笔记变成可检索知识

```text
已认证用户创建或更新笔记
  → 读取笔记正文
  → 按合适长度切成多个片段
  → 调用 Embedding 模型生成每个片段的向量
  → 保存 note_id、user_id、原文片段、顺序和向量
```

`note_id` 用于回到原笔记并生成引用，`user_id` 用于检索时强制隔离用户，原文片段用于真正传给 LLM，向量只用于相似度计算。

创建、更新、删除都要考虑索引同步：

- 创建笔记：新增对应片段和向量。
- 更新笔记：旧片段已经失效，需要重建该笔记的索引。
- 删除笔记：对应片段必须一起删除，不能留下孤立向量。

### 问答路径：从问题到带引用回答

```text
已认证用户提交问题
  → 为问题生成 Embedding
  → 只在当前 user_id 的片段中计算相似度
  → 结合最低阈值取得 Top K
  → 组装“回答规则 + 用户问题 + 检索原文”
  → 调用 LLM
  → 返回回答及所用片段的笔记标题、原文和标识
```

这里有三道不同的安全线：

1. **身份范围**：数据库检索先限制当前 `user_id`，不能检索后再由前端过滤。
2. **证据范围**：提示词要求只根据给出的片段回答，资料不足时明确拒答。
3. **引用可追溯**：接口返回实际使用的片段信息，让用户能检查答案依据。

提示词约束可以降低幻觉，但不能从技术上保证 LLM 绝不犯错。因此第 15 课还需要用明确样例检查引用是否对应、资料不足时是否拒答，以及答案是否加入了片段之外的事实。

- 文本切块：索引路径。

## 12. 复习问题与参考答案

1. **LLM、Embedding 和 RAG 分别是什么？** LLM 根据上下文生成文本；Embedding 把文本转成可比较的向量；RAG 是先检索外部知识、再让 LLM 基于检索内容生成答案的应用流程。
2. **Top K 和最低阈值有什么区别？** Top K 限制最多返回几条，最低阈值判断每条结果是否足够相关；两者需要配合。
3. **向量为什么不能直接作为回答？** 向量用于数学比较，不是面向用户的自然语言，也不包含回答指令。
4. **相似度高为什么不等于答案正确？** 它只表示向量空间中更接近；片段可能不完整、过期或不足以回答，LLM 也可能误解或生成无依据内容。
5. **用户隔离应该发生在哪里？** 建立索引时记录片段归属，检索时在数据库查询层按当前 `user_id` 限制范围，不能依赖前端过滤。
6. **更新或删除笔记为什么必须同步索引？** 否则问答可能检索到旧内容或已删除内容，造成错误引用和数据风险。

## 13. 完整教程

本课先区分 LLM、Embedding、Retrieval 和 RAG，再把系统拆成索引路径与问答路径。索引路径将笔记切成片段、生成向量并保存原文和归属；问答路径将问题转换成向量，在当前用户范围内寻找达到阈值的 Top K 片段，再把问题和原文交给 LLM。

最小实验用二维预制向量代替真实模型输出，通过余弦相似度观察“打分、排序、截取”的检索过程。随后增加最低阈值，证明 Top K 只控制数量，不能独自判断结果是否相关。实验还保留原片段字段，使检索结果能够把原文而不是向量交给生成阶段。

真实项目中需要维护正文与派生索引的一致性，并把现有用户隔离延伸到向量检索。提示词、阈值和引用能降低错误风险，但不能保证模型永远正确，因此后续还要实现拒答与基础评测。
