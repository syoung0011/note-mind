## 1. 本课目标与边界

完成本课后，学习者应当能够：

- 解释“能生成回答”与“回答有依据、可追溯”之间的区别。
- 为检索结果设置最低相关度门槛，在资料不足时稳定拒答。
- 让聊天接口返回回答及结构化引用，包括笔记身份、标题、片段位置、原文和相关度。
- 使用固定的小型问题集检查命中、拒答和引用是否符合预期。
- 通过真实 API 验证有依据回答、无依据拒答和用户数据隔离。

本课只建立适合当前 MVP 的质量护栏和基础评测，不引入 Reranker、混合检索、自动化大模型裁判或复杂评测平台；这些候选能力继续留在 `docs/backlog.md`。

## 5. 检查点 A：先定义什么叫“回答得可靠”

引用、拒答和评测分别解决不同问题：

- **引用**解决可追溯性：用户能看到回答依据了哪篇笔记的哪段原文。
- **拒答**解决依据不足：最高分都达不到最低门槛时，不把无关片段交给模型猜答案。
- **评测**解决可重复比较：使用固定输入和预期结果，避免只凭一次回答的主观感觉判断质量。

本课采用以下最小质量规则：

1. 只有达到最低相关度门槛的片段才能进入回答上下文和引用列表。
2. 没有合格片段时返回统一的资料不足提示，并且不调用聊天模型。
3. 有依据的回答必须返回非空引用；每条引用必须能定位到当前用户的一篇笔记和具体片段。
4. 引用原文必须与真正传给模型的合格片段一致，不能展示模型没有使用的材料。
5. 基础评测至少覆盖：相关问题命中、无关问题拒答、空知识库拒答和引用字段正确。

进入检查点 B 前，先口头思考：

1. 为什么不能只让模型在回答末尾自行写出“来源：某笔记”？
2. 为什么拒答判断应该依据检索分数，而不是让模型自由决定？
3. 为什么评测需要同时包含“应该回答”和“应该拒答”的问题？

这些问题不要求书面作答。进入下一检查点时，AI 会先给出参考答案，再检查模型关系并创建引用数据链的最小骨架。

### 检查点 A 参考答案

1. 模型自行生成的来源只是不可验证的文本，可能写错标题或虚构来源；正式引用必须由后端根据真实检索对象构造。
2. 拒答是应用层的确定性质量规则，应在调用模型前根据检索结果判断，避免模型对相同质量的材料时答时拒。
3. 同时测试正例和反例，才能避免系统走向“什么都回答”或“什么都拒答”两个极端。

易错点：引用和拒答都不能只靠提示词。提示词约束模型表达，后端代码负责真实来源与是否允许回答。

## 7. 检查点 C：最低相关度门槛与统一拒答

Top-K 只能回答“候选中哪几个分数最高”，不能回答“最高分是否已经足够相关”。例如所有片段都与问题无关时，Top-K 仍会选出其中相对最高的片段。最低相关度门槛用于过滤这种“矮子里拔将军”的结果。

本课先把 `0.50` 作为可通过环境变量覆盖的初始阈值，而不是把它当成永远正确的答案。不同 Embedding 模型和笔记数据可能产生不同的分数分布，检查点 E 会通过固定问题集观察并调整。

- `rank_chunks()` 接收阈值，为纯函数离线验证做好准备。
- 聊天路由使用统一的“没有找到足够相关内容”提示；无片段和低分片段都会走这条路径，并且不调用模型。

基础评测的目标不是用几个样例证明系统“已经很智能”，而是把关键质量规则变成可以重复运行的检查。修改阈值、检索或引用映射后，运行同一组用例可以及时发现行为退化。

AI 创建 `backend/examples/rag_quality_eval.py`，使用固定二维向量进行四项确定性检查：

1. 相关问题命中预期笔记并产生引用。
2. 所有候选均低于阈值时返回空结果，表示应拒答。
3. 空知识库返回空结果，表示应拒答。
4. 引用的标题、片段位置、原文和分数与实际检索片段一致。

这个脚本不连接数据库、不访问 Embedding 或聊天模型。它验证质量规则和数据映射，不代表真实自然语言问题的语义效果；真实效果仍需随后通过完整 API 验收。

## 11. 复习问题与参考答案

1. **Top-K 和最低相关度阈值分别解决什么问题？** Top-K 在已有候选中限制数量并保留相对最高分；阈值判断这些最高分是否已经足够相关。只有 Top-K 会在全部无关时仍选出“相对最好”的片段。
2. **为什么正式引用不能由模型自行生成？** 模型文本可能遗漏、写错或虚构来源。引用应由后端从真正进入上下文的检索对象构造，才能定位真实笔记和原文。
3. **为什么没有合格片段时不调用聊天模型？** 模型没有可靠资料可以依据，继续调用会增加费用、延迟和幻觉风险；应用应直接返回确定性的拒答。
4. **为什么阈值不能只凭直觉设置一次？** 不同 Embedding 模型和数据集的分数分布不同。阈值应先设起点，再用相关与无关问题共同观察误拒答和误回答，依据证据调整。
5. **本课固定向量评测能证明什么，不能证明什么？** 它能稳定验证排序、阈值、拒答和引用映射规则；不能证明真实自然语言语义检索效果，因此仍需要真实 API 正反例验收。
6. **拒答为什么返回 HTTP 200 而不是错误状态？** 检索正常完成但资料不足是预期业务结果，不是认证、参数或服务器故障；回答文本和空引用明确表达了结果。

## 14. 完整教程与课程总结

本课在第 14 课“能够检索并生成回答”的基础上增加了三个质量护栏。检索查询通过 `note_chunks.note_id` 联表取得真实笔记标题，并使用 `RetrievalCandidate` 保证片段和来源一起参与评分与排序；`RetrievedChunk` 则把排序后的片段、标题和分数继续交给回答及引用流程。

Top-K 之前增加了最低相关度过滤。默认阈值 `0.50` 可以通过环境变量覆盖；所有候选都低于阈值时，检索结果为空，聊天路由直接返回统一资料不足提示和空引用，不调用聊天模型。这让“用户没有片段”和“用户有片段但与问题无关”共享一条安全、确定的拒答路径。

聊天响应从只有 `answer` 扩展为 `answer` 加 `citations`。每条引用由后端从真正进入模型上下文的检索结果构造，包含笔记 ID、标题、片段位置、原文和分数，不依赖模型自行声明来源。正常回答返回引用，拒答返回空引用。
