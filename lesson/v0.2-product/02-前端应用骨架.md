# NoteMind v0.2 第 02 课：前端应用骨架

> 状态：进行中（运行验收通过，等待检查点 E 提交与合并）

## 1. 目标与范围

建立统一的前端页面外壳和基础视觉规范，让不同页面拥有一致的品牌入口、内容宽度、颜色、间距和控件状态。

本课采用简洁顶部栏，不为尚未实现的功能添加占位导航。登录页面使用公共页面布局，已登录页面使用应用布局；第 03 课接入注册页面，第 05 课再调整笔记工作台内部结构。

本课不新增依赖，不修改后端或认证协议，不实现复杂主题、动画、搜索或 AI 新功能。

## 2. 当前结构与原因

页面渲染路径为 `main.js → App.vue → RouterView → 当前路由页面`。

- `main.js` 创建 Vue 应用、安装路由，并加载全局样式。
- `App.vue` 是应用根组件，目前只有 `RouterView`。
- `RouterView` 根据当前路由显示 LoginView 或 HomeView；它不负责认证，认证仍由已有路由守卫处理。
- 登录页和主页各自定义控件样式；共享规则重复，后续页面容易不一致。
- `base.css` 包含默认深色配色，主页却固定使用白色面板，容易出现文字和背景对比不协调。本课先统一浅色配色。

共享布局组件只负责公共结构，页面组件继续负责各自业务。通过 slot 把页面内容放入布局，能够复用外壳而不复制笔记或登录逻辑。

## 检查点 C：全局样式与局部样式

AI 将基础配色固定为浅色，新增颜色、圆角、内容宽度和页面间距变量。控件、禁用状态、危险操作与错误文本放入 main.css；登录页和主页保留自身布局的 scoped 样式。主页移除重复品牌与用户名，保留页面标题和退出操作。加入窄屏换行和长文本折行，避免基本布局溢出。

CSS 自定义属性通过 `var(--color-primary)` 读取。相同颜色集中声明后，修改变量就能更新所有使用它的规则，减少多个页面颜色不同步的问题。

全局样式由 main.js 导入，对整个应用生效；Vue 的 scoped 样式会被编译为带组件标记的选择器，主要限定本组件元素。它不阻止 CSS 变量继承，也不代表全局样式失效；同一属性冲突时仍遵循 CSS 优先级。因此将共享控件规则集中到全局，并删除原页面中的重复定义。

学习者任务：在 main.css 的 TODO 处为 `a:focus-visible`、`button:focus-visible`、`input:focus-visible`、`textarea:focus-visible` 写一条共享规则，使用 `outline: 2px solid var(--color-primary)` 和 `outline-offset: 3px`。

`:focus-visible` 让浏览器在需要明确焦点提示时显示样式，典型情况是键盘 Tab 导航。outline 不占据盒模型空间，offset 控制轮廓与控件之间的距离；不要移除默认焦点而不提供替代。

保存后在原开发服务器页面刷新，用 Tab 在品牌、导航、用户名输入、密码输入和登录按钮之间移动，确认焦点轮廓可见。将浏览器缩窄到约 375px，确认顶部栏与表单不横向溢出。若后端可用，可再检查登录后的标题、用户名与退出入口。

实际结果：学习者正确补写四种元素的 focus-visible 选择器、轮廓及偏移，并确认键盘焦点和窄屏检查通过。AI 读取实际 CSS 核对正确，仅将选择器后的双空格规范为单空格；未改动学习者实现的逻辑。

## 6. 后续验收方向

### 实际排错：后端正常，前端本地登录却失败

学习者在本地回归时发现登录提示失败，后端独立测试正常。AI 检查 api.js、Vite 配置、环境文件和 Nginx 配置：前端没有本地环境文件，VITE_API_BASE_URL 未配置时使用相对路径 `/api/auth/login`；Docker 中有 Nginx 转发，而本地 Vite 原来没有 proxy。因此默认本地配置缺少 API 转发，登录请求会发给前端服务器，而不是 FastAPI。实际浏览器状态码尚未采集，不能仅凭通用错误文案断定具体状态码。

AI 在 vite.config.js 中增加开发代理，将 `/api` 转发到 `http://127.0.0.1:8000`，保留原路径，因为后端路由已有 `/api` 前缀。changeOrigin 调整转发请求的 Host 为目标主机；浏览器仍向前端同源地址请求，这不需要放宽后端 CORS。Vite 的 server.proxy 用于开发服务器，生产 Docker 继续使用 Nginx，Render 继续使用构建环境中的后端绝对地址。

执行目录为 frontend。停止原 dev 进程后重新执行 `npm run dev`，让新配置生效，然后重新登录。后端应在 8000 端口运行；若使用其他端口，应将代理 target 对应调整。新增代理不负责启动后端。

浏览器开发者工具 Network 中查看登录请求：Request URL 显示前端端口是正常的，因为转发发生在 Vite 服务端。200 表示接口成功；401 通常说明请求已到后端但账号认证失败；404/405 需核对转发与路径；代理终端提示 ECONNREFUSED 需检查后端地址和监听端口。

复习结论：后端独立正常，只能证明后端本身可用，不能证明浏览器请求走到了它。排错应依次核对请求地址、状态码、转发配置与后端日志。本地页面开发无需每次重新构建 Docker；发布前仍应执行部署方式的最终验收。

学习者确认代理修复后登录成功，随后完成检查点 D 全部验收。

### 开发代理是否影响 Docker 部署？

Vite 的 server.proxy 只作用于开发服务器，不会把目标地址写入生产网页。Docker Compose 仍由 Nginx 将 /api 转发到 backend:8000，Render 仍使用构建时设置的公开 API 地址。Docker 构建保持 VITE_API_BASE_URL 留空；如果以后新增本地前端环境文件，应避免让本地绝对 API 地址进入生产构建。本次没有执行 Docker 重新构建验收，不能记录为已验证部署。

## 8. 复习与参考答案

1. AppShell、slot、RouterView 分别负责什么？AppShell 提供公共结构，slot 接收父组件传入内容，RouterView 根据当前路由显示页面。
2. scoped 会阻止全局样式吗？不会；它主要通过生成组件标记选择器限定局部规则，样式冲突仍由 CSS 优先级决定，变量仍可继承。
3. 为什么用 CSS 变量？将共享颜色和尺寸集中定义，减少不同页面修改不同步的问题。
4. 为什么用 focus-visible 和 outline？给键盘操作提供可见焦点，同时通过不占布局空间的轮廓避免控件移动。
5. 后端正常但前端登录失败，先查什么？请求实际地址、状态码、前端代理及后端日志。不能仅凭通用错误信息判断密码错误。
6. 构建通过等于业务通过吗？不等于；构建检查编译打包，浏览器回归检查真实业务操作。
