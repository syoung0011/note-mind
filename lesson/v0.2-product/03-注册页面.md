# NoteMind v0.2 第03课：注册页面

> 状态：已验收通过，等待最终文档提交与推送

## 1. 目标与范围

让新用户可以从登录页进入注册页，填写用户名、密码和确认密码，创建账号后返回登录页。复用现有 AppShell 和基础样式，不增加依赖。

注册只创建账号，不自动登录。这样直接复用已有登录流程，也让学习者理解“创建用户”和“获取访问令牌”的区别。

## 2. 当前接口与数据流

`RegisterView → auth.register → POST /api/auth/register → UserCreate 校验 → 密码哈希 → 保存用户 → UserPublic → 登录页`。

- 注册请求为 JSON，字段为 username、password；与登录接口的表单编码不同。
- 用户名在后端先去除首尾空格并转为小写，再检查 3～50 个字符及字母、数字、下划线规则。
- 密码为 8～128 个字符，不应自动 trim；空格可能是用户密码的一部分。
- 确认密码只在前端用于发现输入错误，不发送给服务器。
- 成功为 201，返回公开用户信息而非令牌；重名为 409，格式错误为 422。
- 前端校验改善反馈，后端校验才是最终边界。密码不写入 localStorage、日志或 URL。

AI 提供最小可运行模板、维护教程、检查实际代码并解释整改；学习者练习核心请求或提交逻辑、运行页面和 Git 工作流。

## 6. 检查点 B：注册请求服务

AI 在 frontend/src/services/auth.js 新增 register(username, password) 骨架，提供接口地址、POST 方法、JSON 类型声明和错误处理。学习者只补写 requestBody 的值；当前骨架会显式提示尚未完成，不会发送空请求。

输入是两个字符串；成功输出是后端返回的公开用户对象；失败通过 throw 交给页面显示。register 不修改 currentUser，也不保存 Token，因为创建账号不等于登录。

JSON.stringify 把 JavaScript 对象序列化为 JSON 字符串。Content-Type 告诉服务端如何解释请求正文；只写 application/json 不会自动转换 body。登录使用 URLSearchParams，是因为登录接口用 OAuth2PasswordRequestForm 接收表单，而注册接口用 UserCreate 接收 JSON。

练习要求：使用函数参数 username、password 组成对象，将 JSON.stringify 的返回值赋给 requestBody。不要加入确认密码，不要打印密码，也不要使用 trim 修改密码。

fetch 的 Promise 在普通 409、422、500 响应时仍会成功返回 Response，因此必须检查 response.ok。只有网络等请求失败通常才直接抛出异常。response.ok 为真表示状态码在 200～299；response.json() 解析响应正文并返回 Promise，async 函数会将其结果传给调用者。

本检查点先不启动页面，也不执行注册请求，避免在练习骨架尚未完成时创建账号。学习者补写后回复确认，AI 读取文件检查并讲解，再进入注册表单检查点。

实际检查：学习者写了 `JSON.stringify(username, password)`，正确选用了序列化函数，但没有先组成对象。第一个参数是要转换的数据，第二个参数是 replacer（转换规则），不是第二个业务字段。因此这里只会序列化用户名字符串，后端无法收到 UserCreate 对象。AI 改为 `JSON.stringify({ username, password })`，并移除教学保护和 TODO。对象属性简写 `{ username, password }` 等价于 `{ username: username, password: password }`。

## 7. 检查点 C：注册表单

AI 创建 RegisterView.vue，接入 /register 路由、登录页入口、注册成功提示和已登录用户的跳转保护。模板复用 AppShell 和 page-card，不引入新依赖。

学习者只补写 passwordsMatch() 的返回表达式：使用严格相等运算符比较 password.value 与 confirmPassword.value。当前固定返回 false，会阻止注册，完成后再开始运行验收。

v-model 将输入值与 ref 连接；在 script 中通过 .value 读写，在模板中 Vue 自动解包。用户名使用 trim 和小写规范化，密码不规范化。required、minlength、maxlength、pattern 提供浏览器基本校验；服务端仍再次校验输入。确认密码只用于前端比较。

@submit.prevent 在浏览器表单通过约束校验后拦截默认提交，调用 handleSubmit，避免页面刷新。handleSubmit 先检查重复提交和密码一致性，再设置提交状态、等待 register、跳转登录；catch 显示错误，finally 无论成功失败都恢复提交状态。按钮和输入在提交时禁用，函数也检查 isSubmitting，避免重复发请求。

成功后清空密码，并通过 registered=1 给登录页显示提示；URL 不传密码。这个参数只是展示提示，不作为注册成功或登录权限的服务端证据。已登录用户访问 login 或 register 时，路由守卫将其送回主页。

本阶段暂未运行浏览器、构建或真实注册，不记录为通过。补写完成后进入检查点 D。

实际结果：学习者正确实现 `return password.value === confirmPassword.value`，使用严格相等比较两个 ref 中的字符串，且没有 trim 密码。AI 检查后仅删除已完成的 TODO 教学注释，未修改学习者逻辑。

## 10. 复习参考答案

1. 为什么 JSON.stringify 只接收一个业务对象？第一个参数是待转换的数据，第二个参数是转换规则；多个业务字段应先组成对象。
2. 注册为什么不保存 Token？接口返回 UserPublic，创建账号和登录是两个不同动作；只有登录接口签发访问令牌。
3. 为什么前端和后端都校验？前端让用户及时发现错误，后端防止绕过页面直接发送非法请求。
4. 为什么需要 response.ok？fetch 收到普通 HTTP 错误仍会返回 Response，业务必须主动判断状态。
5. 为什么要用 finally？成功和失败都需要恢复提交状态，让用户可以继续操作。
6. 确认密码为什么不发给后端？它仅用于前端发现两次输入不一致，注册接口只需要最终密码。
