### 当前认证流程

登录表单 → login 发出用户名密码请求 → 后端返回 Token → 保存 Token → restoreAuth 请求 /api/auth/me → 更新 currentUser → 跳转主页。

Token 是请求携带的凭证；currentUser 是前端已确认的用户状态；isAuthReady 表示初始恢复检查是否完成。三者职责不同：本地有 Token 不等于后端已经确认它有效。

可以自行思考：为什么网络断开不能直接认定 Token 失效？答案会在状态恢复检查点结合实际实现讲解。

学习者在 handleSubmit 入口的 TODO(learner) 处补一条保护：如果 isSubmitting.value 已为 true，立即 return。必须放在清空提示和设置状态之前。

按钮 disabled 防止常规点击，但函数入口保护明确规定正在提交时不能再次进入逻辑，也覆盖其他方式触发函数的情况。JavaScript 在到达第一个 await 之前会先设置 isSubmitting 为 true，因此之后再次调用可以被入口判断拦截。

try 中等待登录并跳转；catch 将失败显示给用户；finally 在成功或失败后恢复提交状态，使用户能再次操作。TypeError 在当前 fetch 流程中通常来自网络连接失败，但也可能来自代码错误，排错时应结合 Network 和控制台，不能把所有 TypeError 都认定为断网。

## 6. 检查点 C：认证状态恢复

AI 调整 restoreAuth 的失败分支：无 Token 或 /me 返回 401 时返回 null；401 还会清除 Token。网络异常、服务器错误和响应解析失败则清空未确认的 currentUser，但保留 Token 并向调用者抛出错误。finally 仍会将 isAuthReady 置为 true，表示本次检查结束，不代表身份确认成功。

初始路由守卫捕获恢复故障，跳到带 reason=unavailable 的登录页；登录页提示检查网络后刷新，或重新登录。刷新会重新运行初始恢复检查。查询参数只决定提示文字，不授予权限。

登录接口返回 401 时，页面展示统一的“用户名或密码错误”；不区分账号不存在或密码错误。其他响应中的 detail 只有字符串时才用于提示，避免把校验错误数组直接显示成无意义文本。

学习者在 auth.js 的 login 内补写 TODO：取得 user 后，如果 user 为空，抛出 Error，阻止继续返回登录成功。错误提示已经写在 TODO 中。只改这一处，然后回复确认。

这里区分三种结果：用户对象表示确认成功；null 表示没有有效身份；抛出错误表示本次无法确认。网络断开并不能证明 Token 无效，所以不能直接删凭证。保留 Token 也不能放行页面，受保护页面仍要求后端确认身份。

实际结果：学习者正确实现 `if (!user) throw new Error('登录状态验证失败，请重新登录')`。null 会触发异常，阻止函数返回成功；用户对象则继续执行。AI 删除已完成的 TODO 注释，未修改学习者实现。

## 7. 检查点 D：使用中失效与主动退出

当前浏览器只接入笔记请求；问答虽已有后端接口，前端没有相应调用，本课不新增问答页面。

笔记服务原本已在错误对象上保存 HTTP status，主页统一的 handleRequestError 因此可以识别 401。AI 将此分支改为清理认证状态，并 replace 到带 reason=expired 的登录页。登录页展示重新登录提示；普通请求故障只显示错误，不清除凭证或跳转。首次恢复身份时已有 Token 却得到 null，访问受保护页面也显示失效提示。

学习者在 HomeView.vue 的 handleLogout 内，将 router.push 改成 router.replace，保留其他代码。

push 追加浏览器历史，replace 替换当前历史项。退出时使用 replace，可以避免后退立即回到刚才的工作台地址；它不能删除所有旧历史，也不能代替路由守卫或后端权限校验。主动退出不显示“认证失效”，因为这是用户主动选择。

当前 logout 只清除本地 Token 和用户状态，不会在服务器撤销已签发 JWT；服务端令牌撤销属于后续安全专题。

此阶段完成后再进行真实浏览器验收，暂不标记请求和跳转已验证。

## 10. 复习与阶段总结

1. 为什么有 Token 不等于登录成功？Token 只是凭证，/me 成功返回用户才表示本次身份确认成功。
2. 为什么网络失败保留 Token？网络失败不证明凭证无效，但未确认身份时也不能放行受保护页面。
3. isAuthReady 为 true 代表已登录吗？不代表；它只表示初始恢复检查结束，登录身份由 currentUser 表示。
4. throw 后页面为什么还能恢复按钮？错误进入 catch，finally 无论成功或失败都会执行。
5. replace 能保证退出安全吗？不能；它改善历史记录行为，权限仍由后端校验，路由守卫控制页面访问。

学习者独立完成提交入口保护、登录用户结果判断及主动退出 replace 修改。AI 提供其余必要实现与解释、删除已完成 TODO 并维护教程。完整教程由第4至11节按实际检查点组织。
