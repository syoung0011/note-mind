切换失败后仍在 feature/basic-feedback，因此 pull 尝试拉取已删除的远程功能分支；删除当前正在使用的分支也会被拒绝。`[gone]` 仅表示上游分支已删除，不表示本地提交丢失。第一条命令失败后应停止，先用 status 确认当前状态，不能继续执行依赖前一步的命令。

恢复步骤在项目根目录逐条执行，每条成功后再继续：

```powershell

# 列出 stash，确认最上方是刚保存的 lesson06 记录。
git stash list
# 恢复最近的暂存文档补充；成功后移除该 stash 记录。

# 核对当前已在 main，且文档补充已恢复。

# 删除已合并的本地功能分支。

```

stash 是临时保存未提交改动，不是正式提交，也不会推送到 GitHub。路径参数限制保存范围，避免收起无关工作。pop 应恢复刚创建的 stash；若冲突，Git 通常保留 stash，停止处理冲突，不重复 pop、不丢弃记录。恢复成功时应只有课程文件仍有修改，main 与 origin/main 同步。本次没有既有 stash，便于辨认。

## 9. 复习与完整教程

本课第1～8节记录分析、状态设计、练习、回归、故障排查、PR、stash 恢复及发布准备，按顺序阅读可复现完整过程。

- 为什么列表失败不能用 notes.length 判断？空数组可能表示尚未获取成功，不能证明没有数据；必须另有失败状态。
- 为什么 catch 后仍需 finally？无论成功失败都要恢复按钮；但请求一直挂起时 finally 不会主动结束等待。
- 为什么错误赋值用 = 而不是 +=？界面应显示本次错误，而不是累积旧消息。
- 为什么健康接口正常仍可能登录失败？当前健康接口不连接数据库，登录注册却依赖数据库。
- 为什么 switch 被拒绝后不继续 pull？当前仍在原分支，后续命令会作用于错误的分支。
- stash 与 commit 有什么区别？stash 临时保存未提交工作；commit 建立正式分支历史。stash 恢复后仍要正式提交。
- 为什么标签不会包含这次最终定档？标签固定到已确认的发布提交，后续文档提交继续前进，不改变已发布版本。
